Operate

Backups, updates, restore and monitoring. Commands run in /opt/wrench on the node.

Backups

The backup container dumps the database and config/ on its schedule (cron, UTC) into a local (data/backup/restic) and an S3 restic repository, both encrypted. Old snapshots are pruned only after a successful run. The dashboard and alerts report a failed or missing backup; WRENCH_BACKUP_HEARTBEAT_URL gets a ping after each one.

Update

docker compose exec backup wrench backup
# set WRENCH_VERSION in .env to the new release
docker compose pull && docker compose up -d

Migrations run at start and are not reversible. To roll back a release that changed the schema, restore the backup taken before the update with the previous version.

Restore

On a clean node with compose.yaml, .env, Caddyfile, initdb/, the restic password and an empty data/ prepared as in Deploy:

docker compose up -d postgres
docker compose run --rm backup restore --from s3 latest
docker compose up -d

The restore needs the database owner, so point the backup at it for that run: add -e WRENCH_BACKUP_POSTGRES_DSN=postgres://wrench:<POSTGRES_PASSWORD>@postgres:5432/wrench?sslmode=disable after --rm. Start Wrench only after the restore.

Monitor

  • The dashboard's top bar shows whether requests run, and why they are paused.
  • Administrators see system status, every user's usage and open alerts.
  • Watch /healthz from outside the node, and use a dead-man check for the backup heartbeat.
